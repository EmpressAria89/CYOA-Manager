# Project audit: 2026-10-16

Status: completed source, native, data-integrity and delivery audit. The private recovery state/logs are indexed by the installed workspace backup README.

## Scope

First-party Vue/TypeScript, Rust, reader adapters, configuration, Linux workflow, packaging/recovery scripts, tests, documentation, source/privacy boundaries, installed runtime and historical backup inventory. Bundled third-party viewer engines were inventoried and compatibility-tested; they were not independently audited line by line.

Live library, builds, edition archives and native browser storage are outside the source tree and are not test targets for mutation. Native fixtures and failure tests use isolated storage. No GitHub push or working-folder Git reattachment is part of this audit.

## Confirmed fixes

| Finding | Change |
|---|---|
| Every library card handled global scroll/resize with its menu closed | Listeners exist only while its menu is open and are removed on close/unmount |
| An older asynchronous cover result could replace a newer cover | Invalidated watcher results are ignored; failed cache entries can retry |
| Concurrent forced library reads could race | Shared serialized refreshes coalesce pending refresh requests |
| Favorite updates used an array index that could move during refresh | Re-find the card by UUID after the response |
| Leaving Library during a download could retain a progress listener | Unmount cleanup and late-registration guard |
| Theme/settings changes caused duplicate writes and font-face reloads | Remove duplicate watcher, serialize/coalesce native preferences, avoid unchanged CSS/writes |
| Startup maintenance refreshed the full library even when unchanged | Refresh only when metadata/reconciliation reports changes |
| A post-commit website cleanup error could delete the committed snapshot | Mark staging committed immediately after database success |
| Failed library startup allowed normal commands against fallback empty state | Keep the error visible and block manager commands until restart after repair |
| Catalog fetching embedded an inherited API key and duplicated work | Use the public keyless endpoint through Rust and share a five-minute memory cache |
| Deep inferred section chains could exhaust recursion | Bound inference depth and preserve authored visibility beyond that bound |
| Already-compressed archives were decompressed and hashed on every maintenance pass | Skip completed compression during startup; opening/restoring and retiring loose files still verify |
| Late perk-search results could repopulate a short/cleared query | Invalidate requests immediately on query changes and unmount |
| Viewer windows could invoke library-management commands | Manager commands require the exact main-window label; website/reader/recovery windows are rejected |
| Unstarred groups without a library card had no clear UI route | Separate Manage automatic backups control; the main Archives list remains starred-only |
| Settings could clip at large text sizes and used cramped spacing | Scrollable page, clearer field spacing, narrow-screen layout and theme-aware status colors |
| Active library filters were tedious to reset | Add Clear filters beside filters and in the no-results state |
| Keyboard/reduced-motion styling lacked a shared baseline | Visible focus, consistent disabled feedback and reduced-motion rules |

## Verification

Final evidence:

- TypeScript/Vite production build passed.
- 39 Rust tests passed; the optional large-export check also passed separately.
- 11 UI/composable suites passed, including four palettes, 100-card listener counts, repeated navigation, delayed covers, serialized refreshes, stale perk searches, clear filters, large-text Settings scrolling, archive management and reader controls.
- Native WebKit DBZ fixture passed rendering, parent close/reopen, retained selections, hidden-choice preview, repeated manual hide/show, display controls, live typography/density and distinct score colors.
- Isolated native startup-failure test kept the corrupt database unchanged and the app running to show its error. Rust authorization tests reject reader/website/recovery commands and all commands after failed startup.
- Read-only live-data review passed: SQLite `quick_check`, 97 library cards with files, 29 archive editions (10 starred), and 32 archive members hashed against their manifests. No data migration, restore or archive deletion was performed.
- Largest-export preparation passed: 405.9 MiB original, 3,127,702-byte browser JSON and 2,022 lossless image resources. Original digest unchanged. One observed preparation took about 1.22 seconds; this is not a repeated scrolling/peak-memory benchmark.
- Preserved Git history passed `git fsck`; only the fork origin is configured. The working source remains detached and no upload was made.
- Source export/readback, documentation links, script syntax, version agreement and Linux-only configuration passed. Linux package assets and executable hashes are checked before installation.

Baseline was 34 Rust tests and nine UI/dependency suites.  JavaScript and Rust dependencies were updated within compatible constraints. Final npm-registry and RustSec scans report no vulnerability findings. RustSec still reports seven unmaintained and two unsoundness warnings in upstream dependencies (including GLib 0.18 and rand 0.7); these are recorded, not suppressed. A safe GTK/Tauri migration is roadmap work. This does not certify third-party bundles, the native system stack or every possible vulnerability.

## Cleanup policy

Remove generated build/test/package staging only after successful readback. Retain the source, regression checks, current runtime/release, current pre-audit snapshot, unique data backups and preserved Git history. Older executable retention is based on verified replacement rollback copies, not filename age alone. The private deletion manifest records exact hashes and outcomes. Nine obsolete files were removed: six intermediate executables and retired Windows/multiplatform tooling/planning files, totaling 186,831,621 bytes (about 178 MiB). The original executable, two newer rollback executables, the current pre-audit source/runtime snapshot, all unique data snapshots and Git history remain. Generated dependency/build/test/package staging is removed after delivery; current runtime and release/export artifacts remain.

## Remaining boundaries

Clippy completed without compile errors; remaining style/API-shape warnings are recorded in private evidence, not represented as a clean warning-free lint pass. Commands and catalog pages remain large legacy modules; broad extraction is proposed in the roadmap rather than combined with behavior fixes. Runtime web content remains untrusted: website IPC restrictions stay enforced. Atomic replacement is not a substitute for a second-disk backup or a power-loss durability design. A successful local run does not prove remote CI or every Linux distribution/CYOA.
